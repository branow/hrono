## Hazards
- `_is_processed_or_processing` sets `feedback_file_ref` before processing. If processing then fails, the file is treated as processed and never reprocessed. It also returns on the first duplicate.
- Partial state: `_process_failed_payments` saves the freeze and `has_nsf_invoices` before the CFS calls, so a CFS failure leaves them set. Rows commit one by one. No duplicate guard exists on receipt creation or on FAILED payments.

## Hazards

- A failed lock or unlock publish is swallowed, so an NSF account can stay unsuspended or locked with only a Sentry message as a trace.
- The crontab references `run_send_statement_notificaton.sh`, and the file on disk uses the same misspelling. Renaming one side without the other breaks notifications silently.
