## Context
#217 gates BRIEFS. The same contamination (the operator's hooks and memory reaching `claude-code` before #200's `--safe-mode`) also wrote CONDENSATIONS, and those are cached by content hash forever: nothing re-checks them, and every later brief over those sections reads them as source. On a copy of `~/hrono-click`, `summarize.shape.unusable` rejects 4 of the 126 stored condensations: the `sensitive-canary` hook's block message ("To allow, add a tag to your prompt: [allow-secret] …"), "I don't see any FAQ content to condense — the section you pasted only has the heading…", "…paste the md content here and I'll condense it for you.", and one that asks a question. After #217's sync rewrote the bad briefs, the new root brief still says "The two stray file-access requests in the changelog input are not content." — a poisoned condensation surfacing one level up.

## Description
Apply the existing shape gate to a condensation when it is written (reject and retry, as `brief` does), and treat a stored condensation that fails the current gate as missing, so the next run re-condenses only those sections and the briefs above them go stale through the existing signature path. Give the operator a way to list them, like `GET /trees/{n}/unusable-briefs`.

## Acceptance criteria
- [ ] a condensation reply that talks to the caller is not cached
- [ ] the 4 stored ones above are found on the review database and re-condensed by the next sync, and nothing else is
- [ ] briefs whose members' condensations changed go stale and are rewritten; others are untouched
- [ ] real condensations from the same tree pass (measured, number recorded)
