## Context
T21, the REDUCE stage of the two-layer recipe: turn each bottom-level topic
(node, #040) into a `brief` by summarizing its sections' condensations (#058).
This is what the tree serves and what upper levels are built from. The recipe is
SETTLED (summarization-experiments.md): the "adaptive" reduce prompt over the
condensations — state what the group is as a whole, find the natural groupings
actually present (never force a structure; must work for code/config/prose
alike), concrete names, compress near-identical chunks into pattern+variations,
ending with a Caution section aggregating the map-stage GOTCHA lines (omitted
when there are none). References are MECHANICAL — chunk URIs appended by code
from node membership, never LLM-written.

## Description
Register a `brief` job op that reduces each in-scope bottom-level node to a
stored brief with provenance:
- Resolve the `brief`-role text model + the seeded `brief`-role prompt (#021) +
  the connection; call via the #057 client. (Same role->model open question as
  #058 — resolve the sole text model for now unless dev finds a role field.)
- Per node: gather its member sections' condensations (#058), render the brief
  prompt over them, get the brief text + token usage.
- **References mechanical**: append the member section URIs to the brief from
  node metadata in code — no LLM tokens, no hallucinated refs.
- **Provenance**: persist, with each brief, which model + which prompt (by name
  and template hash, #021) produced it, and the token usage / cost inputs. This
  is the record freshness (#064) and the estimated_cost API read back.
- Store the brief as a node attribute (a `briefs` table or a column on nodes —
  dev's call, keep it queryable by node + level). A node with no changed inputs
  and an existing fresh brief is skipped (idempotent).
- Lock discipline (like #058/#035): load nodes + condensations under the #008
  lock, RELEASE, LLM calls OUTSIDE the lock, re-acquire to persist. Failure
  isolates to the node's leaf.

## Acceptance criteria
- [ ] `brief` runs as a job over a scope of bottom-level nodes on the #057 client
      and writes one brief per node.
- [ ] The brief is produced by the seeded `brief`-role prompt over the node's
      condensations; no summarization vocabulary is hardcoded in the op.
- [ ] Member reference URIs are appended mechanically from node membership, not
      generated by the LLM.
- [ ] Each brief records provenance: model name, prompt name + template hash,
      and token usage; readable back for cost/freshness.
- [ ] LLM work runs outside the #008 lock; a failing node fails its leaf cleanly;
      re-run over unchanged nodes makes zero new LLM calls.
- [ ] Tests use a FAKE client: brief written per node, mechanical refs present,
      provenance recorded, skip-on-unchanged, failure isolation. `ruff format`,
      `ruff check --fix`, `pytest` clean; committed.

## Out of scope
- Upper levels / `brief-upper` recursion (T22 / #060-062).
- Faithfulness gate (T23.1 / #063) and member-set/prompt-hash staleness (T23.2 /
  #064) — this writes provenance those consume; it does not gate or invalidate.
- Model routing by cluster coherence (deferred open item).
- Export rendering (M6).
