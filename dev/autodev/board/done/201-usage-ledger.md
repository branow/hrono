## Context
Cost visibility was confirmed for the first version, and nothing it needs is stored. `jobs` has no user and no tokens column; a successful 6m30s `maintain` in the review database has an empty `result`. Tokens exist only on `condensations` and `briefs` rows, which records what a stored artefact cost and loses every call that failed, was retried, or was a judge call. Everything in #202 and #203 reads from this ticket's table.

## Description
Record one row per model call, at the single seam every provider goes through (`llm/client.py`), not per provider.

Each row carries: the job that made the call and that job's root run; the user who started the root run; the configured model's name and role; the actual upstream model string; the connection's provider; input tokens, output tokens, and cache-read / cache-creation tokens as separate columns; wall-clock duration; whether the call succeeded; a timestamp. Embedding passes are recorded the same way (tokens may be null, duration is not).

`jobs` gains the user who created the job, set by every enqueue path (API, dashboard, CLI via API). Children inherit the root's user.

`claude-code` currently reports `input_tokens` only, which is how a brief shows "2 in, 5,371 out" — capture its cache token counts too.

A migration, forward-only. Old jobs have no user and no ledger rows; that is shown as unknown, never as zero.

## Acceptance criteria
- [ ] every LLM call made by any op writes exactly one ledger row, including calls that fail and calls that are retried
- [ ] a row names the configured model AND the upstream model actually called, and the provider
- [ ] cache-read and cache-creation tokens are stored separately from input tokens for providers that report them
- [ ] a job records who started it; a child job resolves to its root's user
- [ ] a concurrent pool of calls (HRONO_LLM_CONCURRENCY > 1) loses no rows — driven with the real pool, not a stub
- [ ] a regression test fails if a provider is added that bypasses the ledger
- [ ] the existing per-artefact token columns keep working; nothing that reads them changes

## Out of scope
Prices and money (#202). Any page (#203). Backfilling history.
