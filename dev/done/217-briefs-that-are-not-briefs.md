## Context
The review tree's ROOT brief is: "There's no task here — your message is just system context, no actual child briefs to condense. Paste the briefs (or point me at the <skill> output) and I'll merge them." It is stored, marked "stands", shown on the map, and is the first page of the export an agent would read. A leaf brief ends "say the word if you actually want those files pulled in." Two separate defects.

That skill name appears nowhere in hrono — it is from the operator's personal user-level Claude Code memory. #107 gave the `claude-code` backend an empty working directory to keep PROJECT memory out; USER-level memory still gets in.

Note: `src/hrono/llm/claude_code.py` has uncommitted changes in the working tree as of 2026-10-03. Read them first; part of this may be in flight.

## Description
Isolation. The `claude-code` backend must run with no user memory, no project memory, no user settings, skills or MCP servers influencing the call. Prove it with a probe that would be answered differently if memory leaked, run through the real CLI.

Why the root got no input. The reply says there were no child briefs in the prompt. Find out whether `brief-upper` really sent an empty or malformed prompt for the root on this tree (8 topics, 2 levels) and fix the cause; a refusal that is CORRECT about its input is a pipeline bug, not a model problem.

Gate. A brief is accepted only if it is a brief. Reject and mark for retry output that addresses the operator, asks a question back, refuses, or offers to do something. Start mechanical — the existing faithfulness gate is the precedent — and say in the Review log what it catches and misses, measured against the stored briefs available. A rejected brief is never written as "stands"; the topic shows as needing a brief and the health view counts it.

Existing bad briefs: a way to find them in a built tree and regenerate only those.

## Acceptance criteria
- [ ] a `claude-code` call is unaffected by the user-level CLAUDE.md, user settings, skills and MCP config — proven by a real-CLI probe, with the mechanism named
- [ ] the cause of the empty root prompt is identified and fixed, or shown not to be a hrono defect, with evidence
- [ ] the two briefs quoted above are rejected by the gate; real briefs from a built tree are not — both measured
- [ ] a rejected brief leaves the topic visibly without a brief and counted in health
- [ ] bad briefs already stored can be listed and regenerated without rebuilding the tree
- [ ] the incremental promise holds: regenerating them touches only those topics

## Out of scope
Judging brief quality beyond "is this a brief at all". Prompt changes.
