# insights-recipe: the measured review and extend recipe, and where it lands in hrono
2026-11-02. Generic and private-data-free by design. Sources (private, outside the repo, not to be cited by name in code or docs):
- the insights experiment: its README log, the shared frame, variant frames v4-v7, the extend prompt, the runner (`run.py`), per-run `summary.json` and `tools.json`;
- the blind review series of the hrono arm on the extended brief (scores only);
- hrono code read: `src/hrono/summarize/lookup.py`, `llm/tools.py`, `llm/client.py` (tool loop), `llm/openai.py`, `llm/claude_code.py`, `summarize/build_tree.py`, `tree/sync_chain.py`, `tree/settle.py`, `summarize/briefs.py` (brief_versions, E033), `pins.py`.

## Answer
The cheapest variant that worked ("v7") is ONE agent run per subtree, with a frame prompt that puts the area brief and a one-line-per-topic index up front, tells the agent to grep the condensations (never read a file whole) on six fixed questions in its first turn, then read narrowly and confirm in source. It wrote at most 15 findings, each with evidence. A second call (extend, no tools, $0.39) rewrites the area's upper brief with the findings placed in its sections. Cost: $2.43 and $1.79 on two tries (9 and 8 findings, about 8-11 true, sampled claims confirmed in code), 45 and 34 turns, never near the 80-turn cap. Each run also caught 3-4 wrong statements in the existing briefs. Caveat to carry into the tickets: feeding the extended brief to a downstream agent did NOT raise a blind quality score (22.7/40 vs 24.0 without, 3 runs each; traps avoided 5.7 vs 5.7) but lowered cost per task ($3.46 vs $4.38) and turns (86 vs 99). The step is justified as correcting briefs and surfacing rules, not as a measured score gain.

## What to take
1. Review prompt structure (frame), in this order: role ("the part the cheaper models cannot do; do not summarise or restate; find what a capable developer who read the briefs would still get wrong"); the unit up front; the layers and how to read each; how to work; what to find (3 angles); output format; the area brief and index pasted at the end. Short, direct sentences; no persona padding.
2. Up front, in the prompt: the area's upper brief (about 16k chars) and a ONE-LINE-per-topic index (title, what it is, files; about 380 chars per topic, 14k for 36 topics). The fat index (adds each topic's first hazards, 42k chars for 36 topics) was the $3.96 variant's input; the one-line index cost less and lost nothing measurable. Say "use the whole index: an insight often comes from comparing topics nobody reads together, including old ones."
3. Layers named to the agent: topic briefs (open only when the index line is not enough); condensations (the layer to search: typed lines RULE, STATES, IN, CALLS OUT, ABSENT, each section headed by file and byte range); source (confirm by line range, never whole file). Rule: "Nothing counts until you have read the code that shows it."
4. First turn is breadth: one parallel Grep per question, output capped (head_limit about 40), tight patterns, chosen from what the brief and index call things. The six fixed questions: time (dates, periods, windows, boundaries); money and quantities (summed, and what reverses them); who counts (status, type, rank, market, exclusions); as of when (state at the time or today's); failure and reruns (transactions, locks, truncates, deletes, retries); one or two unit-specific deciders. Then depth: only where members disagree, a rule is in some members and not others, or code looks fragile. Plus the "dropped rule" line: when older members of a family apply a rule newer ones do not, treat it as a rule the newer may have dropped, report it unless code, comment or a deployment script shows it was deliberate; the newest member is what the next change copies. (The generic questions are code-flavoured; for docs or tickets sources, swap in the domain's equivalents but keep the shape: fixed breadth questions, then depth.)
5. Three angles in "what to find": unwritten rules and disagreements among family members; the next change (what a copy of the newest member carries or lacks, history of fixes and guards); invariants and where code holds them only by convention. Each variant alone found different things with little overlap (cross-sibling inconsistencies, bugs fixed in one family only, failure and rerun semantics), so keep all three in one prompt.
6. Finding record, fields in order: one-line statement; angle (rules, next change, invariants); why it matters; evidence (paths with line numbers, read); in the map (where the briefs state it: not stated, only in topic X, misstated in X; and where it should be stated: area or a topic); confidence (high, medium, low, and what would settle it). Then a `Checked and dropped` list (hypothesis and why rejected, one line each) and `Where I looked` (one line). Cap 15 findings, most important first; "fewer good beat many weak; zero is acceptable". Map to the goal's stored fields: statement, evidence (file, lines, version), confidence, placement, dropped hypotheses.
7. Extend prompt (one call, no tools): input is the upper brief and the findings; rules: keep structure, headings and wording and change only what a finding touches; put each finding in the section where its reader needs it (hazard under Hazards, area rule where the flow is described, member difference where members are named), as a statement about the area with its evidence paths in the brief's own style; correct wrong statements in place; no separate Insights section, preamble or edit note; drop nothing unless a finding proves it wrong; return only the full brief. Result: 16.5k to 28.7k chars, same headings, $0.39. A separate insights file was tried first and gave no gain; a section appended to the brief was the form chosen by the owner and tested.
8. Lookups used by v7: Grep 31, Read 12, Write 1 (final file), no Glob, no Search by meaning. v4 (Read 26, Grep 14) was costlier. So: Grep is the main tool, Read by line range, over briefs, condensations and source. hrono maps: `Files.grep/read/glob/search` in `summarize/lookup.py`, paths `source/<source>/...` and `condensed/<source>/...md`.
9. Turn cap: the experiment capped at 80 turns and used 34-52 (33-51 tool calls). hrono's `Toolbox.most` is 15 calls (`MOST_CALLS`, `turns` = most + 2): too low. Build an insights `Toolbox` with `most` of about 60 (all three provider loops already iterate `toolbox.turns`); keep `SPENT` as the soft stop and `REPEATED` free for repeated calls.
10. Model call parameters measured: strong model (Opus-class), one call per pass, one extend call per pass. Estimate for the dry run: about $2-3 per pass plus $0.4 extend; the only measured spread is $1.79-$3.25 per pass.

## Mapping onto hrono
- `summarize/lookup.py`: `files(conn, tree, condense_model)` builds `Files` from `sections` joined to `condensations`, `source_type != 'node'`, so lookups see no briefs. Add brief files (e.g. `brief/<path>.md`) for the subtree under review, and the area's own brief only in the prompt, not as a lookup. Keep the unit scoped to the node's descendants so Grep does not cross the tree. `toolbox(found, own)` takes `most=MOST_CALLS`; add a `most` argument. `OWN` makes reads of a leaf's own files free (brief writer only); not needed here.
- `llm/tools.py`, `client.py`, `openai.py`, `claude_code.py`: the call-answer loop is already common; `THINKING_BUDGET` 4000 is on for tool calls, keep it. `claude_code` takes `max_turns = MAX_TURNS + request.tools.turns`, so a bigger `most` flows through. The extend call is a plain completion (no `tools`).
- `summarize/build_tree.py` level loop and `tree/sync_chain.py`: after `brief_upper` of a level, count unreviewed brief characters below each node (leaf = its brief length, parent = sum of children, reset on a pass); run a pass on a node that reaches the threshold (default 500 000 chars), then continue upward so the parent is clustered and briefed from the extended brief. The root always gets a last pass over what remains. In `sync`, a node whose reviewed brief was rewritten gets a full new pass before its parent; the step is off by default and `sync_chain` already says it does not spend money unasked. `settle` is the place the goal fixes for the passes (`tree/settle.py` ops are staged jobs; add an insights stage there, not a timer).
- Brief versions (E033, `briefs.upsert` writes `brief_versions`, keeps 5): the cheaper brief becomes the previous version with provenance naming the insights model and pass (reason distinct from regen/rewrite). Beware the cap of 5: a re-pass writes another version; a pass must not push out the only cheaper original of a reviewed node; test this.
- Pins (`pins.BRIEF`, `pins.is_pinned`): a pinned (hand-edited) brief is never overwritten; keep and show its findings, do not apply. Check `is_pinned` before the extend write, not before the review.

## Traps
- Cost is context growth: every read stays in context and is paid again on each turn. The $3.96 variant read whole condensation files (about 25k chars each) and long code ranges; context reached 276k tokens. Instruct "grep, then read sections by line range" and cap grep output.
- Coverage is the agent's choice: a fixed first-turn question list widened it a little but the same few topics got most reads; one rule that mattered was seen in old members and dismissed as legacy until the "dropped rule" line was added, and even then judgment varied run to run (a finding reported in 3 of 5 runs). Expect partial recall; run one pass per node, do not promise completeness.
- Findings describe hazards of existing code; a downstream agent building something new may not turn them into "my code must do X" (measured, no score gain). Write findings as rules for anyone adding to the area, as the extend prompt does.
- Repeat runs overlap only partly (3 of 8 repeated); one pass is a sample, not a sweep.
- The brief must be corrected in place: every run found 3-4 false statements in the cheaper briefs; a pass that only appends leaves them.

## Rejected
- Three separate prompts (conventions, next change, invariants), about $3.25 each and $11.38 for three: one prompt with all three angles got comparable true findings for a third of the cost.
- v4 (fat index, read whole files): $3.96, no wider coverage.
- v5 (grep with self-chosen concepts): $2.98, missed a whole class of rule because it chose its concepts itself; fixed questions (v6) fixed that, $2.52.
- A separate insights file next to the brief: no gain over none and the owner wants findings inside the brief.
